# Suly Plus

منصة تجارة إلكترونية متعددة المتاجر (Multi-tenant SaaS) بواجهة عربية RTL، مبنية باستخدام React وTypeScript وSupabase.

## التقنية
- React 18 + TypeScript + Vite 6
- Supabase PostgreSQL وAuth وStorage وEdge Functions وRow Level Security
- React Router 6 وTailwind CSS 3
- Vitest + Testing Library

## تشغيل المشروع محليًا
1. ثبّت Node.js 22.12 أو أحدث وGit.
2. استنسخ المستودع.
3. نفّذ `npm install`.
4. انسخ `.env.example` إلى `.env.local`.
5. تأكد من وجود `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY` في `.env.local`.
6. نفّذ `npm run dev`.

## أوامر المشروع
- `npm run dev` — تشغيل بيئة التطوير
- `npm run typecheck` — فحص TypeScript
- `npm test` — الاختبارات
- `npm run build` — بناء نسخة الإنتاج
- `npm run preview` — معاينة نسخة الإنتاج

## الوظائف المتصلة حاليًا
- التسجيل وتسجيل الدخول والخروج عبر Supabase Auth.
- إنشاء المتجر وربطه تلقائيًا بصاحبه كمالك.
- إدارة بيانات المنتجات والعملاء والطلبات من PostgreSQL.
- واجهة متجر عامة تعرض المنتجات المنشورة.
- سلة مشتريات محلية لكل متجر مع تعديل الكميات وحذف العناصر.
- إتمام طلب ضيف بالدفع عند الاستلام.
- احتساب الأسعار من قاعدة البيانات، والتحقق من توفر المخزون، وإنشاء الطلب وبنوده وخصم المخزون وتسجيل حركة المخزون في معاملة واحدة.
- تأكيد الطلب وتتبع حالته من خلال رقم الطلب ورمز وصول عشوائي.
- عكس حجز المخزون عند إلغاء الطلب.
- سجل لعمليات الدفع وجدول لمعاملات بوابة الدفع المستقبلية.
- صور المتاجر والمنتجات في Storage bucket باسم `store-assets`.

## Edge Functions
- `create-guest-order`: إنشاء طلب ضيف والتحقق من البيانات وتحديد معدل المحاولات.
- `get-order-status`: إظهار حالة الطلب بمفتاح تتبع سري، دون كشف بيانات العميل أو عنوانه.

مصادر Edge Functions محفوظة في `supabase/functions` وإعدادات النشر في `supabase/config.toml`.

## حدود الدفع الحالية
طريقة الدفع المفعلة حاليًا هي **الدفع عند الاستلام فقط**. لم يتم ربط Paymob أو أي بوابة دفع إلكتروني بعد. قبل تفعيل الدفع الإلكتروني يجب توفير بيانات حساب التاجر من مزود الدفع، ثم إضافة عملية إنشاء جلسة الدفع والتحقق من توقيع Webhook وتحديث حالة الدفع من الخادم فقط. لا يتم اعتماد أي عملية دفع بناءً على استجابة المتصفح.

رسوم الشحن والضرائب والخصومات لم تُفعّل بعد؛ حاليًا الإجمالي هو مجموع أسعار المنتجات المحفوظة في قاعدة البيانات.

## الأمان
- المفتاح الموجود في الواجهة هو Publishable Key فقط، والوصول للصفوف محكوم بسياسات RLS.
- لا تضع أبدًا `service_role` أو Secret Key في ملفات `VITE_*` أو في المتصفح.
- إنشاء الطلبات العامة وتتبّعها يمران عبر Edge Functions، ودوال قاعدة البيانات الحساسة لا يمكن استدعاؤها بمفتاح المتصفح.
- يتم حساب السعر على الخادم ولا يُقبل سعر يرسله العميل.
- يتم قفل صفوف المنتجات أثناء التحقق من المخزون وحجز الكميات لمنع البيع الزائد في الطلبات المتزامنة.
